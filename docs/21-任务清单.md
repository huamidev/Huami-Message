### P1 · 新消息提醒（**不做真推送**）

**决定：用第三方证书，所以真推送做不了**
（APNs 密钥属于「团队」，别人的团队建不了）。

**替代方案：后台刷新 + 本地通知。这个不需要付费账号。**

- [ ] `Config/Info.plist` 加 `UIBackgroundModes: fetch`
- [ ] App 里注册 `BGAppRefreshTask`，定期拉一次新消息
- [ ] 拉到新消息时发**本地通知**（`UNUserNotificationCenter`）
- [ ] 点通知进入对应会话

> **缺点要说清楚：时机完全不保证。**
> iOS 是看心情调度的 —— 用户常用这个 App、电量充足、连着 Wi-Fi 时会勤一点，
> 否则可能几小时才给一次机会。所以它是「比完全不知道强」，不是真推送。
>
> 另外：第三方证书**随时可能被 Apple 批量吊销**。
> 一旦发生，用户手机上已装的 App 会**直接打不开**（不是提示重装，是闪退），
> 得换一张证书重新装。这是选这条路要接受的代价。

| **消息删不掉**（`messages` 没有 DELETE 权限）| 不影响使用。要做的话得先想清"删除是给谁删"（只删我这边，还是所有人）—— 不是加一句 SQL 的事 |

## 📌 几个踩过的坑（改代码前先看一眼）

**1. 别在被保护的表上写递归的权限规则。**
`conversation_members` 的读规则里查 `conversation_members` 会
`infinite recursion`，整套功能 500。要包进 `security definer` 函数
（内部绕过 RLS），并且**显式写死 `search_path`**。

**2. 给数据库加字段时，插入和更新**两条路都要改。
这个坑踩过三次（`imageURLString` / `avatarURL` / 音频字段），
现在三处都用"统一覆盖"方法收口了。

**3. `print` 在 Xcode 控制台里能看到，`os.Logger` 不一定。**
排查信息必须真的到达对方眼睛，否则等于没写。`AppLog` 现在两样都发。

**4. SwiftUI 的 `DragGesture` 要等"识别"，UIKit 的 `touchesBegan` 不用。**
按住类交互（录音）要用 `LongPressGesture(minimumDuration: 0)` 的
`pressing` 回调，否则静止按住时会卡到系统手势闸门超时。

**5. 音频会话的 `setActive` 在主线程会卡住 UI。**
要放到 detached task 里。录音和播放两条路都要。

**6. 加接口字段时注意命名策略。**
我们的 `JSONDecoder` 开了 `.convertFromSnakeCase`，
属性名必须写 **camelCase**（`accessToken`），照抄 JSON 的
`access_token` 会永远 `keyNotFound` —— 而错误信息看起来像"服务器拒绝了"。
