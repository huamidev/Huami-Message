# 网页版方案（让安卓朋友也能用）

## 一句话

**后端一行都不用改。** 网页版是**新的一套前端**，连的是同一个 Supabase。

|---|---|

**网页端要做的只是「界面 + 把这套接口调对」。**

## 哪些要重写

iOS 版的数据层是 Swift（本地优先：先读本地库、再后台同步）。
网页版用 **`@supabase/supabase-js`** —— 登录、刷新凭证、实时订阅、
文件上传它都包好了，所以**这一层比 iOS 那边省事得多**。

但下面这些**设计决定要照着抄**（它们是踩过坑换来的，不是随便定的）：

1. **消息按「账号 + id」定位**，不能只按 id
   （否则换个账号左右会全反 —— 这是真实踩过的坑）
2. **本地数据按账号隔离**，墓碑也一样
3. **发送 optimistic**：先画到界面上，再发；失败了标红可重试
4. **绝不静默失败**：拉不到就出声，别让用户以为是空的

## 三个必须提前知道的现实

### ① 国内访问会不稳

Cloudflare Pages 在国内**时通时不通**。这不是代码问题，是网络问题。
如果朋友用起来觉得经常打不开，只能换国内主机 —— 而那需要域名 + ICP 备案。

### ② 通知（网页版比 iOS 版更受限）

- **安卓 Chrome**：PWA 推送可以用 ✅（比 iOS 版还强，iOS 版没有推送）
- **iOS Safari**：**必须先「添加到主屏幕」** 才有推送，而且限制很多 ⚠️
- 桌面浏览器：正常 ✅

### ③ 语音消息的格式

iOS 录的是 **m4a**，浏览器录的是 **webm/opus**。
两种格式互相播不了 —— 所以要么统一转码，要么各播各的。
**建议各播各的**（iOS 播 m4a、网页播 webm，都能播对方的？不能）。
真要互通，得在服务器上转码（Edge Function + ffmpeg）。

**里程碑 7 的时候再定这件事**，先记在这里。

## 技术选型

| | 选它 |
|---|---|
| 构建 | **Vite**（快，配置少）|
| 语言 | **TypeScript**（消息、会话这些结构抄 iOS 的模型，类型能挡住一批错）|
| 界面 | **React**（生态最熟，出问题好查）|
| 后端客户端 | **@supabase/supabase-js** |
| 样式 | 先用一份手写 CSS，沿用 iOS 那套浅色配色 |

**不引入 UI 组件库**：聊天界面长得太特殊，组件库的默认样式反而要一条条覆盖掉。
