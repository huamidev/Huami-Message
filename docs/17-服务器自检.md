# 服务器自检：让 App 自己说清楚哪里没配好

> 这一轮没有加功能，解决的是一件很实际的事：
> **接上真服务器之后，有三件事必须在 Supabase 后台手动做。漏掉任何一件，
> 报错都很难懂。**

---

## 一、问题：配置漏了会以很难懂的方式失败

你这个项目里，"开发者"和"用户"是同一个人。而漏配置的后果是：

| 漏了什么 | 表面上看到的现象 | 实际原因 |
|---|---|---|
| 没跑 `schema.sql` | 注册成功，但登录之后什么都没有 | 数据库里根本没有表 |
| 没关「Confirm email」 | 注册完登不进去，等邮件等不到 | Supabase 免费版邮件限流极严 |
| 没部署 AI 云函数 | 润色一直转圈 | 函数不存在 |

日志里出现的通常是 `PGRST205` 这种没人看得懂的东西。

**与其让人去翻文档，不如让 App 自己说清楚要去点哪里。**

---

## 二、做了什么

登录页现在会自己做三项检查，有问题就**把"去点哪里"直接列出来**：

```
🔧 服务器还有 2 项没配置好

  数据库的表还没建
  没有表就存不了账号资料、好友和消息。
  现在注册会成功，但登录之后什么都看不到。
     1. 打开 Supabase 控制台，左侧点 SQL Editor
     2. 点 New query
     3. 把项目里的 supabase/schema.sql 全部复制、粘贴进去
     4. 点 Run，看到 Success. No rows returned 就对了

  邮箱验证还开着
  开着的话，注册完必须去邮箱点确认链接才能登录……
     1. Supabase 控制台左侧点 Authentication
     2. 找到 Sign In / Providers，点 Email
     3. 把 Confirm email 关掉
     4. 点 Save
```

**它是自己会消失的**：配置正确的服务器上三项全过，界面什么都不显示。
不需要有人记得上线前删掉。

---

## 三、一个差点埋下的误报

第一版检查"AI 云函数部署了没有"用的是 `GET` 请求。

但真实部署之后，函数**未必响应 GET** —— 那样就会误报"还没部署"，
让人去查一个根本不存在的问题。

改成发一个**专门的探针**（`mode=ping`），并且：

- 云函数对 `ping` 是**直接返回、不调用 DeepSeek** 的 ——
  **一个健康检查不该花钱**
- 用 `POST` 而不是 `GET`，和真实调用同一条路径

这个细节值得记：**检查本身也会有 bug，而且误报比不报更糟**
（不报只是没帮上忙，误报会让人去修一个不存在的问题）。

## 四、验证记录

| 场景 | 结果 |
|---|---|
| 真实项目（表没建、邮箱验证开着） | ✅ 正确列出 2 项，步骤可照着做 |
| 假服务器（表存在、函数存在） | ✅ 0 项问题，卡片不显示 |
| 探针是否只在前面都通过时才发 | ✅ 是（日志顺序确认） |
| 网络临时故障 | ✅ 不报（那种情况刷一下可能就好了，弹提示反而让人以为坏了） |
