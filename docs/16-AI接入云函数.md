## 一、为什么 AI 要绕一圈走云函数

不能直接连 DeepSeek，因为那需要把 API Key 写进 App。
App 装到手机上就是一个压缩包，**任何人解开来都能看到里面的字符串**。
Key 一旦泄露，别人会拿它刷 token，**账单是你的**。

所以：App 只认识云函数的网址 → 云函数拿着 Key 去问 DeepSeek → 结果流式转发回来。
Key 只存在服务器的环境变量里。

代码在 `supabase/functions/ai-proxy/index.ts`（上一轮写的），
客户端在 `Huami Message/Services/SupabaseAIService.swift`。

## 二、顺手改掉一个设计缺陷：失败必须能说出来

原来的 AI 协议返回的是**不会抛错的流**：

```swift
func polish(...) -> AsyncStream<String>
```

这对假数据没问题（假数据不会失败）。但真网络**失败是常态**：断网、超时、
AI 额度用完、云函数挂了。

用不抛错的流，这些情况只能"安静地什么都不发生" ——
用户盯着一个永远转不完的圈，我们连个日志都没法给他看。

所以改成了 `AsyncThrowingStream`，并且：

- **润色**：三张卡片各自显示自己的错误（它们是并发跑的，可能只有一张失败，
  所以不能只在顶上挂个横幅）
- **小助手**：在聊天记录里显示一张红色的错误卡片，而不是留着"正在想…"

## 三、这一轮抓到的三个 bug（都很难靠读代码发现）

### bug 1：弹窗被无声吞掉，但里面的请求照样发出去

日志显示 AI 请求发出去了，**但润色页根本没显示**。

原因：启动时登录用的全屏覆盖（`fullScreenCover`）还盖在最上面时请求弹窗，
会被**无声吞掉** —— 不报错、不警告，就是什么都不显示。

**更坑的是：弹窗里的 `.task` 照样会跑。** 所以 AI 请求发出去了、钱花了，
用户却什么都看不见。

> 这是我在这个项目里**第二次**踩同一类问题（第一次是"加好友"页）。
> 经验：**凡是弹窗 / 全屏覆盖，都要留意它们之间的时序。**

### bug 2：我的假服务器是单线程的

三个润色请求并发发出，但服务器**只收到一个**。

原因不在客户端，在**我的测试工具**：Python 的 `HTTPServer` 是单线程的，
而我把协议设成了 HTTP/1.1（客户端默认复用连接）。
单线程服务器在一个连接关闭前不会处理别的连接 —— 于是后两个请求永远排着队。

改成 `ThreadingHTTPServer` 之后，三个风格同时到达 ✓。

> 这个坑很值得记：**它看起来像"客户端并发有问题"，其实是测试工具的限制。**
> 如果我不查下去，可能会去改客户端的并发逻辑，把好代码改坏。

### bug 3：Swift 的自动解码器**会忽略属性的默认值**

最隐蔽的一个。小助手的方块一个都显示不出来，日志只有一句
「收到一个看不懂的方块」。

原因是这段代码：

```swift
struct DecisionOption {
    var id: UUID = UUID()          // ← 这个默认值解码时不起作用
    var label: String
    var percent: Int
    var isRecommended: Bool = false // ← 这个也一样
}
```

**自动合成的 `init(from:)` 会忽略默认值**，照样要求 JSON 里有这些字段。
而服务器不会发 `id`（那是客户端自己用的），推荐标记也只在高概率那一项上发。

结果是解码直接失败，而且错误信息完全联想不到"默认值"这三个字。

修法：自己写 `init(from:)`，能缺的字段缺了就用默认值补。
（写在 `extension` 里，这样自动生成的构造函数还在，假数据那边照样能用。）
