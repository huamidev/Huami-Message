# App 图标与小助手形象

> 你给的那张图（一只圆脑袋、闭着眼、头顶小芽、嘴里叼根草的线稿角色）
> 现在同时用在了两个地方：**App 图标** 和 **小助手的形象**。

---

## 一、用在了哪里

| 位置 | 用法 |
|---|---|
| **App 图标** | 角色放在主色蓝 `#12B7F5` 上，占画面 82% |
| **聊天页的「小助手」按钮** | 20pt，就是一个能认出来"是谁"的小脸 |
| **小助手面板顶部** | 56pt + "我是小助手" + 一句说明 |

**为什么按钮上既放脸又写字**：输入框左边已经有一个 ✨（润色），两个都挨得近。
脸让人一眼认得出"这是小助手"，文字则保证不会和润色搞混。

## 二、原图不能直接用，做了三步处理

原始素材有三个问题：

1. **白底**（1203×1203，无透明通道）—— 直接合成到蓝底上会变成一个白方块
2. **留白不对称** —— 角色偏右、左边留了一大块给那根草。直接做图标，角色是歪的
3. **线稿太细** —— 缩小之后糊成一团

处理流程（工具在 [assets-source/](../assets-source/)）：

```
去白底(key)  →  自动裁到内容边界(trim)  →  合成到纯色底(icon)
```

- **去白底**：按"像素越暗越可能是线条"算透明度（`alpha = 1 - 最暗通道/255`），
  再提一点对比。这样抗锯齿产生的浅灰边缘会得到**半透明**，而不是一圈生硬的白边。
  保留原始 RGB，所以**那根绿草还是绿的**。
- **自动裁边**：扫描透明通道，找出内容边界，四周留 24px 边距。
  裁完角色自然居中。
- **合成**：纯色底 + 角色按比例居中，输出 1024×1024。

## 三、两个必须记住的坑

### ① App 图标不能有 alpha 通道 ⚠️

我第一版做完，`sips -g hasAlpha` 报的是 **yes** —— 上传 App Store 会被直接拒。

**关键点**：哪怕每个像素都是不透明的，只要 PNG 文件里**带了 alpha 通道**就不行。
所以画布必须用 `CGImageAlphaInfo.noneSkipLast`，而不是 `premultipliedLast`。

生成后一定要核对：

```bash
sips -g pixelWidth -g pixelHeight -g hasAlpha ".../AppIcon-1024.png"
# 期望：1024 / 1024 / hasAlpha: no
```

### ② `sips` 的裁剪偏移语义不直观

我试了一次 `sips --cropOffset 0 0 -c 620 1206`，拿到的区域和"左上角"对不上。
裁剪是要精确到像素的操作，用不可靠的工具会反复返工 ——
所以这里自己写了个 `imgtool`，坐标以**左上角为原点**（和看图时的直觉一致）。

顺便：`sips` **能**做缩放和格式转换，这两件事用它没问题。

## 四、想改的时候怎么改

完整命令写在 [assets-source/README.md](../assets-source/README.md)。

**换底色**（第 4 步最后两个参数是底色和角色占比）：

```bash
./.tmp/imgtool icon ./.tmp/char-trim.png ./.tmp/appicon.png 1024 FFFFFF 82
#                                                             ↑底色  ↑占比%
```

**换形象**：把新图放进 `assets-source/`，重复那四步。或者直接替换
`Huami Message/Assets.xcassets/AssistantAvatar.imageset/` 里的三张 PNG
（1x / 2x / 3x 分别是 64 / 128 / 192 像素）。
