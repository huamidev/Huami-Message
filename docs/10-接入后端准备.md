> 你去注册账号的时候，我把后端需要的东西**先写好了**。
> 这样等你把账号开好，接线只需要很短的几步，而不是从零开始搭。

## 一、我已经准备好的两个文件

### 1. `supabase/schema.sql` —— 数据库结构 + 权限规则

在 Supabase 控制台的 SQL Editor 里整个粘进去 Run 就行。

包含 5 张表和 8 条权限规则：

| 表 | 放什么 |
|---|---|
| `profiles` | 用户档案（昵称、头像色、邀请码） |
| `friendships` | 好友关系 + 拉黑标记 |
| `messages` | 消息 |
| `reports` | 举报记录 |
| `deletions` | 删除墓碑（同步删除用） |

**权限规则（RLS）是这份文件里最重要的部分。**
没有它，任何人拿到 anon key（它是公开的、就写在 App 里）
就能读走整个数据库里**所有人的聊天记录**。

一句话概括它做的事：**每个人都只能碰和自己有关的数据。**

### 2. `supabase/functions/ai-proxy/index.ts` —— AI 中转云函数

这是保证 **API Key 不落到 App 里** 的关键。App 把要问 AI 的内容发给它，
它加上 Key 再去问 DeepSeek，然后一段段转发回来。

Key 只存在 Supabase 后台的环境变量里，**App 那边永远看不到它**。

## 二、几个设计决定，以及为什么

这些决定以后想改会比较贵，所以值得说清楚。

### 消息的 id 由客户端生成，不是服务器自增

因为我们做了**本地优先**：消息先写进手机本地、立刻显示，再送服务器。
如果等服务器分配 id，本地那条和服务器那条就对不上号，
"发送中 → 已发送"的状态替换就无从谈起。

### 好友关系存两行（A→B 和 B→A）

这样每个人都能有自己的拉黑标记：你拉黑了他，**不影响他那边看到你**。
存一行再查两次虽然省空间，但每次查询都要 OR 两个方向，很容易写错。

### 拉黑在服务器端也拦

只在客户端拦是不够的 —— 对方换个客户端、或者直接调接口，照样能发进来。
所以 `messages` 的插入策略里有一条：**对方拉黑了我，服务器直接拒收**。

### 删除要留墓碑

否则你在这台手机上删了，换台设备登录，删掉的东西又被同步拉回来了。
（这个坑我们在本地数据库那一层已经踩过一次，见 [03-本地优先数据层.md](03-本地优先数据层.md)。）

### 加好友靠邀请码，不上传通讯录

通讯录是隐私雷区，审核也容易出问题。邀请码让用户自己决定给谁。

### 没用 pgcrypto 扩展

生成邀请码本来可以用 `gen_random_bytes()`，但那需要额外装 pgcrypto。
换成了 PostgreSQL 13 起内置的 `gen_random_uuid()` ——
**少一个依赖就少一个"注册时报错但不知道为什么"的可能。**

## 三、账号好了之后，我们的顺序

### 你要亲手做的（我会逐步给指引）

1. **跑 `schema.sql`**
   Supabase 控制台 → SQL Editor → 粘贴 → Run
   （可以重复运行，写了很多 `if not exists`）

2. **部署云函数**
   ```bash
   supabase functions deploy ai-proxy
   supabase secrets set DEEPSEEK_API_KEY=sk-你的一串
   ```
   这一步需要装 Supabase CLI，我会给你命令。

3. **在 Apple Developer 后台开启 Sign in with Apple**
   这是唯一一步我完全没法代劳的 —— 需要你的开发者账号。

4. **把这两个值发给我**（它们是公开的）：
   - Project URL
   - anon public key

### 我来做的

5. **写 `SupabaseChatService`** —— 实现 `ChatService` 协议。
   **所有界面代码一行都不用改**，因为从一开始界面就只跟协议说话。
   这是当初那道"插座防火墙"的回报。

6. **接入「通过 Apple 登录」**

7. **做邀请码加好友的界面**

8. **把 AI 从假数据换成真的** —— 实现 `AIService` 的云函数版，
   同样不用改界面。

9. **联调** —— 这一步的时间取决于会遇到什么问题，不好预估。

## 四、要提前想好的一个决定

**「删除账号」现在只删本地。** 接上服务器之后，它还要删服务器上的数据。

Apple 那边有个额外的要求：如果 App 提供第三方登录（我们用的是 Apple 登录），
删除账号时**必须同时删除用于登录的凭证**，不能只是标记为"已停用"。
到时候我会用 Supabase 的 service_role 在云函数里做这件事。
