# 网页版部署到 Cloudflare Pages

## 一句话

构建产物是一堆静态文件，传到 Cloudflare Pages 就行。
**不需要服务器、不需要数据库、不需要配环境变量** ——
后端（Supabase）已经在跑了。

---

## 先确认构建是好的

```bash
cd web
npm install          # 第一次才需要
npm run build
```

成功的话会看到 `dist/` 里有：

```
index.html
assets/index-xxxx.js        ← 打成一个包
assets/index-xxxx.css
manifest.webmanifest        ← PWA 清单
sw.js                       ← Service Worker（离线壳）
icon-192.png  icon-512.png  apple-touch-icon.png
_redirects
```

想先在本机看一眼正式版（和部署后一模一样）：

```bash
npm run preview
```

---

## 部署方式一：网页上传（第一次最省事）

1. 打开 https://dash.cloudflare.com → **Workers & Pages** → **Create** → **Pages**
2. 选 **Upload assets**（不是连 Git）
3. 把 `web/dist` 这个**文件夹**整个拖进去
4. 项目名随便起（比如 `huami-message`）
5. 完事之后会给你一个网址：`https://huami-message.pages.dev`

**这个网址就能发给安卓朋友了。**

---

## 部署方式二：连 Git（以后改了自动发布）

1. 把这个项目推到 GitHub
2. Cloudflare Pages → **Connect to Git** → 选仓库
3. 构建设置：
   - **Root directory**: `web`
   - **Build command**: `npm run build`
   - **Build output directory**: `dist`
4. 以后每次 push，它自动重新构建发布

---

## 部署方式三：命令行

```bash
cd web
npx wrangler pages deploy dist --project-name huami-message
```

会要求登录 Cloudflare（浏览器里点一下授权）。
适合"改完就想立刻发一版"。

---

## ⚠️ 三件必须知道的事

### ① 国内访问会不稳

`*.pages.dev` 在国内时通时不通，这不是代码问题。

如果朋友普遍反映打不开，只有两个办法：
- 换国内主机 —— 需要域名 + **ICP 备案**（个人备案现在不容易，可能几周）
- 或者先凑合：让打不开的人挂梯子（对他来说这不是"能用"）

**这一条建议先问清楚朋友的网络环境再决定。**

### ② 换域名之后要改一处

Supabase 后台 → **Authentication → URL Configuration**：
把新网址加进 **Redirect URLs** 白名单。

不加的话，**注册时的确认邮件点回来会失败**（跳不回你的网站）。
登录本身不受影响，所以这个坑要等到有人注册才会暴露。

### ③ 加了新版本之后，用户可能还看到旧的

Service Worker 会缓存 App 的壳。它设计成"下次打开自动更新"，
但用户如果一直不关页面，可能拿到旧版本。

真要立刻生效：Cloudflare 后台可以 **Purge cache**，
或者改 `web/public/sw.js` 里的 `CACHE` 版本号（现在是 `huami-shell-v1`）。

## 手机上"装"成 App

- **安卓 Chrome**：打开网址 → 右上角菜单 → **添加到主屏幕**。
  之后就是一个独立图标，打开没有地址栏，和 App 一样。
- **iOS Safari**：分享按钮 → **添加到主屏幕**。
  ⚠️ iOS 上必须这么做才有推送 —— 而且限制很多。

## 检查清单（部署完照着点一遍）

- [ ] 能打开首页，看到登录页
- [ ] 能登录（用现有账号）
- [ ] 会话列表有内容
- [ ] 能进聊天、能发消息、对方能收到
- [ ] 发一张图片
- [ ] 发一条语音，**在 iOS 上点开能听见**（这条最关键）
- [ ] 重启浏览器，还是登录状态
- [ ] 添加到主屏幕，图标和名字对
