# 加好友：用邀请码，不读通讯录

> 这一轮补上的是**最大的一个缺口**：朋友装上 App 之后谁也加不了、一句话也说不了。
> App 做得再顺，加不上好友就还是空的。

---

## 一、为什么用邀请码，不读通讯录

几乎所有人第一反应都是"读通讯录自动匹配好友"。我没这么做：

- **要弹权限。** 用户看到「这个 App 想访问你的通讯录」，很容易直接卸载
- **等于把关系网整个上传。** 你的通讯录里有别人的名字和电话，
  那些人**没有同意过**任何事。这是个很重的隐私承诺

邀请码反过来：**由用户决定给谁**。多一步，但那条线守住了。

对一个"帮朋友之间把话说好"的小工具来说，这个取舍是划算的。

---

## 二、做了什么

```
Services/ChatService.swift        + addFriend(inviteCode:) 协议 + ChatError
Services/MockChatService.swift    + 假实现（从码派生出稳定的假好友）
Stores/ChatStore.swift            + addFriend
Features/Friends/AddFriendView.swift   加好友页（含二维码）
Features/Messages/ConversationListView.swift  工具栏「+」+ 空状态出口
Features/Messages/ChatView.swift  空会话提示
```

一页管两件事：**把我的码给别人**、**把别人的码输进来**。
放一页是因为它们本来就是同一个动作的两面。

### 几个细节

- **邀请码 8 位，去掉了容易看错的 `0/O/1/I`** —— 这个码是要用户手打的
- **用等宽字体显示**：`8` 和 `B`、`0` 和 `O` 用比例字体看起来太像
- **输入时就过滤**（只留字母数字、强制大写、最多 8 位），
  比点按钮之后再报错友好得多
- 加成功之后**显示加的是谁**（"已添加 顾南"），只说"成功"两个字的提示没有用

### 假实现里的一个关键约束

假实现没法去服务器查"这个码是谁"，所以**从邀请码本身派生出假好友** ——
同一个码永远得到同一个人。

这一点很重要：如果每次加都随机生成一个人，
那「加两次会不会变成两个好友」这类问题就**永远测不出来**。

而且派生 UUID 时**故意没用 `UUID(uuidString:)!`** ——
我在这个文件里已经被强制解包坑过一次了（见 `MockChatService.swift` 里的注释）。
直接用 16 个字节构造，没有"字符串格式对不对"这一层，也就没有崩的可能。

## 三、二维码：我做了真验证，不是"看着对"

二维码有个特点：**糊了、缺白边，肉眼完全看不出来**，只有扫的时候才发现。

所以我用 macOS 的 Vision 框架**真的扫了一遍截图**：

```swift
let request = VNDetectBarcodesRequest()
try VNImageRequestHandler(cgImage: cg).perform([request])
```

结果：

```
✅ 识别成功  类型: VNBarcodeSymbologyQR
   内容: 2G9ED8K9        ← 和界面上显示的邀请码完全一致
```

代码里有两个容易踩的点，都注释了：

- **必须 `.interpolation(.none)`** —— 平滑缩放会让格子糊掉，扫不出来
- **必须留白边**（quiet zone）。二维码规范要求四周有空白，
  贴着别的元素会扫不出。代码里的 `.padding(10)` 就是干这个的

> **"看着对"和"能用"是两件事。** 能自动验证的，就别用眼睛判断。

## 四、踩到的两个坑

### 坑一：全屏覆盖还在上面时，请求弹窗会被**无声吞掉**

启动自检要自动打开「加好友」，但第一次完全没反应 ——
不报错、不警告，就是什么都不发生。

**原因**：启动时登录用的 `fullScreenCover` 还盖在最上面。
在那个覆盖还在的时候请求 sheet，会被直接丢掉。

**修法**：等覆盖消失后再请求（开发自检里加了延迟）。

> 这个坑在做登录页时也遇到过一次（那次是环境没传进去、直接崩）。
> **凡是"弹窗 / 全屏覆盖"，都要留意它们之间的时序。**

### 坑二：空会话的提示被底部面板盖住了

内容比屏幕短的时候，`.defaultScrollAnchor(.bottom)` 会把内容**压到底部**，
于是提示文字正好落在底部面板底下 —— 「说点什么吧」那行完全看不见。

**修法**：把空态从滚动内容里拿出来，做成**覆盖层**，
再往上留出面板的高度。

> 通用经验：**"内容比屏幕短"是一种独立的状态**，要单独看。
> 它和"内容很多"的布局行为完全不同。
