# 账号与登录：用邮箱注册

> 这一轮做了 App 的登录系统。**还没有接服务器** ——
> 现在跑的是本机假实现，但整条链路（注册 → 登录 → 退出 → 再登录）已经通了。

---

## 一、为什么是「邮箱 + 密码」

这不是随便选的，是**约束逼出来的唯一可行解**：

| 方案 | 为什么不行 |
|---|---|
| **手机号 + 验证码** | 国内短信签名需要主体资质报备。**阿里云已明确不再接受个人自用资质申请**（[官方公告](https://help.aliyun.com/zh/sms/product-overview/announcement-on-sms-not-supporting-application-for-personal-use-qualification)）。个人开发者办不下来 |
| **通过 Apple 登录** | 需要付费开发者账号（它是一个 capability）。你现在还没办 |
| **微信登录** | 需要主体认证；而且苹果指南 4.8 规定：提供第三方登录就**必须同时提供 Apple 登录**。绕不开 |
| **邮箱 + 密码** | ✅ 不需要付费账号、不需要资质、免费、**现在就能做完** |

### 两个坑我提前避开了

**① Supabase 免费版自带的邮件服务限流极严**（每小时几封，只够测试）。
所以第一版会**关掉邮箱验证** —— 注册完立刻能登录，**整条主路径一封邮件都不发**。

代价是没办法验证邮箱是真的（有人可以乱填）。对朋友测试没关系，
正式上线后要打开验证，那时候需要一个自己的邮件服务。

**② 找回密码需要发邮件**，这个第一版先不做 —— 界面上点「忘记密码」会如实告诉你
"还没接邮件服务"。等你接一个免费邮件服务（比如 Resend，每月 3000 封免费）再补。

## 二、做了什么

```
Services/AuthService.swift      账号模型 + 登录的「插座协议」+ 会出的错 + 校验规则
Services/MockAuthService.swift  本机假实现（现在用的）
Stores/AuthStore.swift          登录状态总管家
Features/Auth/AuthGateView.swift 登录 / 注册页
```

界面顺序变成了**两道闸门**，顺序不能反：

```
打开 App
   ↓
① 同意服务条款（审核要求，也要让用户看懂我们拿数据做什么）
   ↓
② 登录 / 注册（没有身份的话，谁也加不了谁）
   ↓
主界面
```

### 沿用了一直在用的那套架构

登录也是一个「插座协议」。现在插的是**假电**（数据存在本机），
等你把 Supabase 开好，换成 `SupabaseAuthService` ——
**界面代码一行都不用改**。

这已经是第三个用这套写法的模块了（聊天、AI、登录）。
它一次比一次便宜，因为模式已经固定：
**界面只认协议，不认实现。**

### 一个安全细节

登录时「邮箱不存在」和「密码不对」返回的是**同一个提示**。

这不是偷懒 —— 分开提示等于告诉别人"这个邮箱注册过"，
那是一种可以被用来探测用户的信息泄露。大厂都是这么做。

## 三、写的时候踩到一个坑（值得记）

第一版一启动就崩，崩溃栈顶是：

```
libswiftCore   _assertionFailure
SwiftUICore    EnvironmentValues.subscript.getter
```

**原因**：`AuthGateView` 里写了 `@Environment(AuthStore.self)`，
但我把 `.environment(auth)` 加在了 `TabView` 上，
而 `.fullScreenCover` 是**之后**才挂上去的 ——
弹出来的内容**没有继承到**那个环境，取不到值就直接断言崩溃。

**修法**：在弹窗内容上**再显式注入一次**。

> **通用经验：弹窗 / 全屏覆盖的内容，环境要显式传一遍。**
> 不要假设它会自动继承。

这类崩溃的特点很好认：**栈顶一定是 `EnvironmentValues.subscript.getter`**，
而且信息里会提到缺了哪个类型。以后看到这个就直接去查环境注入。

## 四、现在的实际效果

- 「我」页会显示真实账号：邮箱前缀当昵称、邮箱、**邀请码**
- 邀请码先摆出来 —— 加好友的功能接上服务器就能用，
  但"我的邀请码是什么"这件事现在就该让用户看得到
- 有「退出登录」

邀请码生成时去掉了容易看错的 `0/O/1/I`，因为**这个码是要用户手打的**。
